## 🗺️ 全书结构（预读后写）
- 这本书讲了什么？（一句话）：教你从零构建 Claude Code 式的 Agent Harness——Agency 来自模型，Harness（工具+知识+观察+行动接口+权限）来自工程，17 章逐层加一个机制。
- 核心理念：**Agent 产品 = 模型 + Harness**；反对"提示词水管工"式的流程编排，agency 是训练出来的，harness 才是工程师造的载具。
- 结构框架（17 章，五个阶段，递进式）：
  - **第一阶段·核心循环（s01-s04）**：agent loop → tool use → permission → hooks —— 一个循环 + 工具 + 安全边界
  - **第二阶段·上下文与记忆（s05-s09）**：todo_write → subagent → skill_loading → context_compact → memory —— 让 agent 在有限上下文里长期工作
  - **第三阶段·任务与调度（s10-s12）**：task_system → background_tasks → cron_scheduler —— 从单次对话到持久任务
  - **第四阶段·多 Agent 与扩展（s13-s14）**：agent_teams → mcp_plugin —— 协作协议与外部工具生态
  - **第五阶段·集成与高级形态（s15-s17）**：integrated_harness → workflow_runtime → goal_loop —— 所有机制合一 + 编排与自主判断的边界
- 辅助材料：`agents/` 参考实现（s01-s12 + s_full 全量版）、`skills/` 示例技能、`tests/` 测试

### s01 Agent Loop — 一个循环就够了
- **本章讲了什么**（2~3 句话）：Agent 的最小内核就是一个 `while True`：把消息+工具定义发给模型 → 响应含 `tool_use` 块就执行工具、把结果作为 user 消息喂回去继续循环；不含就退出。模型负责决策（调不调、调哪个），harness 负责执行（跑命令、回喂结果）。三十多行代码就是一个可运行的 agent harness 内核。
- **与前面章节的关系**（递进/展开/举例/转折，为什么放在这里）：首章，全书地基。后续 16 章都是在这个循环上叠加机制，循环本身始终不变。
- **实战场景**（在工作/生活/项目中怎么用）：判断任何"agent 框架"时先看它的核心循环长什么样；自己写自动化 agent 时，先实现这个最小循环再逐步加机制，而不是一上来套重型框架。
- **我的思考**（认同/不认同什么、想到什么、为什么）：*（待补充——你的思考）*
- **我的问题与解答**：

#### 📚 本章拓展资料与对照（2026-10-14 补充）

| 资料 | 类型 | 与本章关系 | 关键说法 |
|------|------|------------|----------|
| ReAct 论文（Yao et al., arXiv:2210.03629, 2022） | 学术论文 | **学术源头** | 让 LLM 交替生成"推理轨迹（thought）+ 行动（action）"，推理帮模型规划/纠偏，行动的结果反哺推理——本章的 loop 就是 ReAct 的工程落地版 |
| Anthropic《Building Effective Agents》(2024-12) | 官方博客 | **赞同+更 nuanced** | "最成功的实现用的是简单可组合的模式，而非复杂框架"；但明确区分 workflow（预定义代码路径编排）vs agent（模型自主指挥），各有适用场景 |
| OpenAI《A Practical Guide to Building Agents》(2025) | 官方指南 | 赞同 | 同样把 agent 定义为"模型+指令+工具的循环"，强调从单 agent 做起、逐步加 guardrails |
| LangGraph（LangChain 阵营） | 框架 | **反方** | 主张用显式状态图编排 agent——正是本书批评的"编排派"的代表，但它强调可控性/可观测性/人在回路 |

- **分歧点**：本书说"一个循环就够了"，编排派说"显式图才有可控性"。
- **辩证结论（我的判断）**：两者其实在回答不同问题——**学习/理解 agent 本质时循环视角最优**（本书立场）；**生产环境中流程可预测、需审计合规时，workflow 更稳妥**（Anthropic 博客也这么说）。有趣的是本书 s16 自己会讲"模型决定单步，脚本决定编排"，说明作者最终也承认编排有其位置——读到 s16 时回来验证。
