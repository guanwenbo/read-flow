## 🗺️ 全书结构（预读后写）
- 这本书讲了什么？（一句话）：教你从零构建 Claude Code 式的 Agent Harness——Agency 来自模型，Harness（工具+知识+观察+行动接口+权限）来自工程，17 章逐层加一个机制。
- 核心理念：**Agent 产品 = 模型 + Harness**；反对"提示词水管工"式的流程编排，agency 是训练出来的，harness 才是工程师造的载具。
- 结构框架（17 章，五个阶段，递进式）：
  - **第一阶段·核心循环（s01-s04）**：agent loop → tool use → permission → hooks —— 一个循环 + 工具 + 安全边界
  - **第二阶段·上下文与记忆（s05-s09）**：todo_write → subagent → skill_loading → context_compact → memory —— 让 agent 在有限上下文里长期工作
  - **第三阶段·任务与调度（s10-s12）**：task_system → background_tasks → cron_scheduler —— 从单次对话到持久任务
  - **第四阶段·多 Agent 与扩展（s13-s14）**：agent_teams → mcp_plugin —— 协作协议与外部工具生态
  - **第五阶段·集成与高级形态（s15-s17）**：integrated_harness → workflow_runtime → goal_loop —— 所有机制合一 + 编排与自主判断的边界

## 📝 核心内容（2026-10-14 全书精读一轮后整理）

### 核心观点
1. **Agent 产品 = 模型 + Harness**。Agency（感知/推理/行动）来自模型训练，不是代码编排；工程师造的是载具。全书 17 章证明：一个 `while True` + 一个工具就是最小 agent，其余一切机制都是"长在循环边缘的注入点"，循环骨架从未改写。
2. **机制的演进主线**：能行动（s01 循环 / s02 工具分发）→ 有边界（s03 权限 / s04 hooks）→ 能持续工作（s05 todo 外化计划 / s06 子 agent 隔离上下文 / s07 技能按需加载 / s08 上下文压缩 / s09 跨会话记忆）→ 能持久协作（s10 任务系统 / s11 后台任务 / s12 定时调度 / s13 多 agent 团队）→ 接开放生态（s14 MCP）→ 集成与自主的边界（s15 全量集成 / s16 workflow 编排 / s17 目标循环）。
3. **自主与编排不是对立而是分工**：s16 明确"模型决定单步，脚本决定编排"，workflow 被收编为循环内的一个工具；s17 连"何时停止"都交给独立判断器裁决。s01 的"一个循环就够了"是先破后立的教学策略——先理解本质，再谈工程约束。
4. **反复出现的设计哲学**：错误文本化（Error 是上下文不是终止符）、工具返回值里教模型下一步、机制注入点在循环边缘、权限/记忆/停止都要防注入——"模型是可信的决策者，但环境输入不可信"。

### 重要概念 / 金句
> Agency 是训练出来的，不是编出来的；模型是驾驶者，harness 是载具。（README）

我的理解：这句话决定了架构分层——任何"用代码堆逻辑来模拟智能"的做法（复杂规则树、硬编码路由）都是在错误的一层用力；harness 的职责是提供感知、行动、边界和记忆，让模型的能力安全地释放出来。评估一个 agent 系统时，先问：哪些是模型的能力，哪些是 harness 的机制，有没有人在 harness 层试图"编出"智能。

### 全书悬念的回收（精读验证记录）
- s01 问题①"循环始终不变"→ **成立**：s15 集成 14 章机制后仍是 `while True` + tool_use 判定；s16 连编排引擎都被包装成循环内的一个工具；s17 只改了"退出"的语义（终止信号→停止提案），不改结构。
- s01 问题②"s16 是否承认编排价值"→ **明确承认**：路径可预测用编排（换并行保证/稳定结构/可恢复），不可预测用模型循环——与 Anthropic《Building Effective Agents》殊途同归。

### 我的疑问与异议
- ❓各章基于 Kimi 端点实测，部分行为（如 s08 thinking 块撑大上下文、s09 模型绕过管线直接写记忆文件）可能与 Claude 官方模型不同——"Anthropic 兼容"≠行为一致，课程文档自己也有此警告。结论迁移到其他模型时需重新验证。
